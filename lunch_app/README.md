# 社内昼食注文システム（lunch_app）

社員が毎日の昼食をブラウザから注文し、担当者が仕出し屋への発注数と
個人ごとの食数をまとめるためのアプリです。
今まで手書きしていた月間の注文用紙を、そのまま置き換えることを狙っています。

同じリポジトリにある注文伝票システム（めっき）とは**独立したアプリ**で、
データベース・ログインアカウントも別に持ちます。

## 用紙との対応

| 手書きの用紙 | このアプリ |
| --- | --- |
| 縦：社員の名簿 | 社員マスタ（並び順を用紙に合わせられます） |
| 横：日付 | 提供日 |
| マスの記号（○ ◎ △ R P） | 注文区分：定食・丼／うどん／そば／ラーメン／パスタ |
| 1 マスに 1 記号 | 1 人 1 日 1 食（選び直すと上書き） |
| 斜線 | 「なし」 |
| 下段の日別集計 | 発注集計（区分別の食数） |
| 右端の食数合計 | 月次集計（21 日〜翌月 20 日） |
| 来客用の行 | 来客用（担当者がまとめて入力） |

## できること

### 社員
| 画面 | 内容 |
| --- | --- |
| 昼食を注文 | 集計期間（例：8/21〜9/20）の全日を一覧表示。日ごとに区分をタップして、まとめて保存。締切前なら何度でも変更できる |
| パスワード変更 | 初回ログイン時は変更が必須 |

スマートフォンから使うことを想定した画面です。献立名も日付ごとに表示されます。

### 管理者
| 画面 | 内容 |
| --- | --- |
| 発注集計 | 日ごとの区分別食数（社員・来客・合計）。印刷と Excel 出力、社員別内訳、注文していない人の一覧、締切後の代理入力、来客用の入力 |
| 月次集計 | 社員ごとの食数と区分別内訳（21 日〜翌月 20 日）。Excel 出力（社員別集計＋日別明細の 2 シート）、日別の食数 |
| 献立編成 | 仕出し屋さんの週間メニューを 1 週間分まとめて入力。他の週からのコピーも可 |
| 社員 | 社員マスタ（追加・編集・無効化・削除・パスワード再設定・管理者権限・並び順） |
| 設定 | 締切のタイミングと時刻、月次集計の開始日、仕出し先名、注文区分 |

### 献立の入れ方
1 日につき「定食・丼の献立名」「麺の献立名」「麺の種類」を入力します。
麺の種類で **うどん・そば** を選ぶと、その献立が「うどん」と「そば」の
両方の区分として登録されます（用紙の運用と同じ）。
空欄にした区分は、その日は注文できません。

### 締切のルール
- 「提供日の何日前の何時まで」を設定できます（既定：前日 10:00）。
- 社員は締切まで自由に変更・取消ができます。先の日付は締切前ならいつでも入力できます。
- 締切後の修正は、管理者が「発注集計」画面の **代理入力** から行います。

## Windows のパソコンで動かす（社内 LAN 運用）

サーバー役のパソコンを 1 台決めて、そこで起動します。社員はブラウザで
そのパソコンの URL を開くだけで、インストールは不要です。

### 1. Python を入れる（初回のみ）
https://www.python.org/downloads/windows/ から Python をインストールします。
インストール画面の **「Add python.exe to PATH」に必ずチェック**を入れてください。

### 2. セットアップ（初回のみ）
`lunch_app\windows\setup.bat` をダブルクリックします。
必要な部品が自動でインストールされます（数分かかります）。

### 3. ファイアウォールを開ける（初回のみ）
`lunch_app\windows\firewall-allow.bat` をダブルクリックします。
管理者権限の確認画面が出たら「はい」を押してください。

これをしないと、**スマートフォンや他のパソコンからつながりません**
（サーバー役のパソコン自身からは開けます）。

### 4. 起動する
`lunch_app\windows\start.bat` をダブルクリックします。
黒い画面にアクセス先の URL が表示されます。

```
  このPC          : http://localhost:5002
  社内の他の端末  : http://192.168.1.50:5002
```

**この黒い画面は閉じないでください。** 閉じるとサーバーが止まります。

### 5. iPhone・Android から使う
1. スマートフォンを**社内の Wi-Fi** につなぐ（モバイル通信では使えません）
2. Safari や Chrome のアドレス欄に、上の「社内の他の端末」の URL を入力する
   - 例：`http://192.168.1.50:5002`
   - **`http://` から入力してください。**省くと検索になってしまいます
3. ログインする
4. iPhone なら 共有ボタン → **「ホーム画面に追加」** をしておくと、
   次からアプリのように 1 タップで開けます

### 6. パソコン起動時に自動で立ち上げる（任意）
`lunch_app\windows\autostart-register.bat` をダブルクリックすると、
Windows の起動時に自動でサーバーが立ち上がるようになります。

### 7. 最初にすること
1. ブラウザで URL を開き、`admin` / `admin1234` でログイン（パスワード変更を求められます）
2. 「設定」で締切と月次集計の開始日（用紙どおりなら **21**）、仕出し先名を設定
3. 「社員」で社員を登録
4. 「献立編成」でその週の献立を入力

### スマートフォンからつながらないとき

| 症状 | 確認すること |
| --- | --- |
| ページが開かない | スマートフォンが**社内の Wi-Fi** につながっているか（モバイル通信になっていないか） |
| ページが開かない | サーバー役のパソコンで `start.bat` の黒い画面が開いたままか |
| ページが開かない | `firewall-allow.bat` を実行したか |
| 検索結果が出てしまう | `http://` から入力しているか |
| 昨日までは使えたのに開かない | パソコンの IP アドレスが変わった可能性があります（下記） |
| 反応がなくなる | パソコンがスリープしていないか（電源設定でスリープを「なし」に） |

**IP アドレスを変わらないようにする**
初期状態ではパソコンの IP アドレス（`192.168.1.50` の部分）が
再起動などで変わることがあります。変わると URL も変わってしまうので、
ルーターの DHCP 予約か、Windows の固定 IP 設定でこのパソコンの
IP アドレスを固定しておくことをおすすめします。

社内のネットワークが「ゲスト Wi-Fi」など端末どうしの通信を禁止する設定
（プライバシーセパレータ／AP アイソレーション）になっていると、
同じ Wi-Fi でもつながりません。その場合はネットワーク管理者にご確認ください。

### バックアップ
`lunch_app\lunch.db` が全データです。このファイルを USB メモリや共有フォルダに
コピーしておけば、パソコンが壊れても復旧できます。

### 社員をまとめて登録する
人数が多い場合は CSV から一括登録できます。
`社員番号,氏名,部署,ログインID,初期パスワード` の順に並べた CSV（UTF-8）を用意して、

```
cd lunch_app
.venv\Scripts\python.exe -m flask --app app add-users users.csv
```

## 開発者向け

### ローカルで動かす（Mac / Linux）

```bash
cd lunch_app
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python app.py          # 開発用サーバー http://localhost:5002
python run_server.py   # 本番用サーバー（waitress）
```

初回起動時、管理者が 1 人もいなければ `admin` / `admin1234` を自動作成します。

### 環境変数

| 変数 | 既定値 | 説明 |
| --- | --- | --- |
| `SECRET_KEY` | `secret_key.txt` に自動生成 | セッション署名鍵 |
| `DATABASE_URL` | `lunch_app/lunch.db`（SQLite） | PostgreSQL を使う場合は `postgresql://...` |
| `PORT` | `5002` | 待ち受けポート |
| `SESSION_TIMEOUT_MINUTES` | `120` | 無操作での自動ログアウト時間 |
| `LUNCH_ADMIN_USERNAME` / `LUNCH_ADMIN_PASSWORD` | `admin` / `admin1234` | 初回起動時に作る管理者 |

### テスト

```bash
cd lunch_app
pytest tests -q
```

インメモリ SQLite で 22 件のテスト（締め期間の計算、締切、1 日 1 食の上書き、
提供外区分の拒否、献立編成、代理入力、来客用、集計、Excel 出力、権限）が動きます。

### ファイル構成

```
lunch_app/
├── app.py              # アプリ生成・共通フック・CLI コマンド
├── run_server.py       # 本番用サーバー（waitress）＋ LAN の URL 表示
├── config.py           # 設定（環境変数・SECRET_KEY の保存）
├── extensions.py       # SQLAlchemy / CSRF
├── models.py           # User / MealType / DailyMenu / Order / GuestOrder / Setting
├── timeutil.py         # 日本時間・締め期間（21日〜20日）の計算
├── utils.py            # ログイン要求・締切判定
├── blueprints/
│   ├── auth.py         # ログイン・パスワード変更
│   ├── orders.py       # 社員の注文（期間まとめ入力）
│   ├── admin.py        # 献立編成 / 社員 / 設定 / 代理入力 / 来客用
│   └── reports.py      # 発注集計・月次集計・Excel 出力
├── templates/          # Jinja2 テンプレート
├── static/css/lunch.css
├── windows/            # Windows 用のスクリプト（setup / firewall-allow / start / autostart）
└── tests/              # pytest
```

### データモデル

- `MealType`（注文区分）… 定食・丼／うどん／そば／ラーメン／パスタ。名称と並び順は設定画面で変更可
- `DailyMenu`（日次献立）… 「その日に提供する区分」と献立名。行がある区分だけ注文できる
- `Order`（注文）… 社員 1 人 × 1 日 = 1 行（`user_id` と `serve_date` で一意）
- `GuestOrder`（来客用）… 日付 × 区分ごとの人数
- `Setting` … 締切・締め日などの設定

### スキーマを変更するとき
テーブルは起動時に `db.create_all()` で作成されます。列の追加・変更を伴う改修を
行う場合は、Alembic の導入を検討してください。
