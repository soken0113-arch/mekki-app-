# 社内昼食注文システム（lunch_app）

社員が毎日の昼食（弁当）をブラウザから注文し、担当者が仕出し屋への発注数と
個人別の月次金額を集計するための Flask アプリです。
同じリポジトリにある注文伝票システム（めっき）とは**独立したアプリ**で、
データベース・ログインアカウントも別に持ちます。

## できること

### 社員（一般ユーザー）
| 画面 | 内容 |
| --- | --- |
| 昼食を注文 | その日の献立から数量を選んで注文。締切前なら何度でも変更・取消ができる |
| 私の注文履歴 | 月ごとの注文明細と支払い金額の合計 |
| パスワード変更 | 初回ログイン時は変更が必須 |

スマートフォンからの利用を想定したレイアウトです（＋／−ボタンで数量を入力）。

### 管理者
| 画面 | 内容 |
| --- | --- |
| 発注集計 | 日付ごとのメニュー別発注数・金額。印刷と Excel 出力、社員別内訳、締切後の代理入力 |
| 月次集計 | 社員別の食数と金額（給与天引き・集金用）。Excel 出力（明細シート付き）、日別推移 |
| 献立編成 | その日に提供するメニューを選択。当日価格・数量上限の設定、他の日からのコピー |
| メニュー | メニューマスタ（名称・価格・説明・表示順・表示/非表示） |
| 社員 | 社員マスタ（追加・編集・無効化・削除・パスワード再設定・管理者権限） |
| 設定 | 注文の締切時刻、仕出し先名 |

### 締切のルール
- 締切時刻（既定 10:00）は「設定」で変更できます。
- 社員は **提供日の締切時刻まで** 追加・変更・取消ができます。翌日以降の分はいつでも入力できます。
- 締切後の修正は、管理者が「発注集計」画面の **代理入力** から行います（数量 0 で取消）。
- 数量上限を設定したメニューは、上限を超える注文を受け付けません。

## セットアップ（ローカル）

```bash
cd lunch_app
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

export SECRET_KEY="$(python3 -c 'import secrets;print(secrets.token_hex(32))')"
python app.py          # http://localhost:5002
```

- 初回起動時、管理者が 1 人もいなければ `admin` / `admin1234` を自動作成します
  （初回ログイン時にパスワード変更が必須。環境変数 `LUNCH_ADMIN_USERNAME` /
  `LUNCH_ADMIN_PASSWORD` で変更できます）。
- サンプルのメニューを入れる場合: `flask --app app seed-menu`
- 管理者を追加する場合: `flask --app app create-admin <ログインID> <パスワード>`

## 環境変数

| 変数 | 既定値 | 説明 |
| --- | --- | --- |
| `SECRET_KEY` | ランダム生成 | セッション署名鍵。**本番では必ず固定値を設定**（未設定だと再起動でログアウト） |
| `DATABASE_URL` | `sqlite:///lunch_app/lunch.db` | PostgreSQL を使う場合は `postgresql://...` を指定 |
| `SESSION_TIMEOUT_MINUTES` | `120` | 無操作での自動ログアウト時間 |
| `LUNCH_ADMIN_USERNAME` | `admin` | 初回起動時に作る管理者のログインID |
| `LUNCH_ADMIN_PASSWORD` | `admin1234` | 同パスワード |

`.env.example` を参考にしてください。

## 本番配備

```
web: gunicorn -w 2 -b 0.0.0.0:$PORT "app:create_app()"
```

- `lunch_app/Procfile` をそのまま使えます（Render / Heroku 等）。
- `SECRET_KEY` と `DATABASE_URL`（PostgreSQL）を設定してください。
- テーブルは起動時に自動作成されます（`db.create_all()`）。
  既存テーブルの列を変更するような改修を行う際は、Alembic の導入を検討してください。

## 運用の流れ

1. **管理者**「メニュー」で弁当の種類と価格を登録する（最初の 1 回）。
2. **管理者**「献立編成」で、その日に提供するメニューを選ぶ（前日までに。他の日からコピーも可）。
3. **社員** 各自「昼食を注文」で数量を入力する（締切時刻まで変更自由）。
4. **管理者** 締切後に「発注集計」を開き、印刷または Excel 出力して仕出し屋へ発注する。
   欠席・追加があれば同じ画面の代理入力で修正する。
5. **管理者** 月末に「月次集計」で社員別の食数・金額を Excel 出力し、給与天引き／集金に使う。

## テスト

```bash
cd lunch_app
pytest tests -q
```

インメモリ SQLite で 19 件のテスト（ログイン、締切・上限のチェック、集計、
Excel 出力、管理者権限の保護など）が動きます。

## ファイル構成

```
lunch_app/
├── app.py              # アプリ生成・共通フック・CLI コマンド
├── config.py           # 設定（環境変数の読み込み）
├── extensions.py       # SQLAlchemy / CSRF
├── models.py           # User / MenuItem / DailyMenu / Order / Setting
├── timeutil.py         # 日本時間の日付ヘルパー
├── utils.py            # ログイン要求・締切判定
├── blueprints/
│   ├── auth.py         # ログイン・パスワード変更
│   ├── orders.py       # 社員の注文・履歴
│   ├── admin.py        # メニュー / 献立 / 社員 / 設定 / 代理入力
│   └── reports.py      # 発注集計・月次集計・Excel 出力
├── templates/          # Jinja2 テンプレート
├── static/css/lunch.css
└── tests/              # pytest
```

### データモデル

- `MenuItem`（メニューマスタ） … 弁当の種類と標準価格
- `DailyMenu`（日次献立） … 「その日に提供する `MenuItem`」。価格はその日の値を保持するため、
  後からマスタ価格を変えても過去の集計金額は変わりません
- `Order`（注文） … 社員 1 人 × 日次献立 1 件で 1 行（数量で複数個に対応）
- `Setting` … 締切時刻などの設定を key/value で保持
